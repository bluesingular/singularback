The three levers you must control:
1. Which model runs each task (routing by complexity = 80% cost reduction on simple tasks)
2. How many tokens the context can consume per heartbeat (hard cap = cost certainty)
3. How many tasks are included before overage kicks in (volume cap = revenue floor)

Without all three, you don't have a business — you have a subsidy programme for your customers.

Model routing is the single biggest lever on your COGS. Routing a simple task to Haiku instead of Sonnet costs 15x less. Done correctly, your blended cost per task drops from €0.09 to €0.02.

The routing implementation rule: Every SKILL.md file must declare its tier in frontmatter. The platform enforces it. No skill can run at a higher tier than declared without operator approval. This makes costs predictable at the skill level before you even run the task.

Three layers of protection. Each is independent. Together they make your cost structure predictable to within ±5% per customer.

Layer 1 — Token budget per heartbeat
Every heartbeat has a hard token ceiling per tier (see routing table)
If an agent would exceed its tier's token budget: truncate context, not output
Context truncation priority: oldest org memory first, then secondary research, then task history
Core context (Company DNA, current task, goal) is never truncated
Agent always informed: "Context was compressed — older memory omitted"
Layer 2 — Monthly token budget per plan
Solo: 5M tokens/month included (≈ 500 avg tasks)
Growth: 20M tokens/month included (≈ 2,000 avg tasks)
Pro: 60M tokens/month included (≈ 6,000 avg tasks)
Dashboard shows token burn in real-time (shown as tasks remaining, not raw tokens)
Alert at 80%. Hard pause at 100% unless operator increases cap.
Layer 3 — Overage pricing (cost-positive)
Overage priced at 3× your marginal LLM cost — always margin-positive
Solo overage: €0.024/task equivalent (your cost ~€0.007)
Growth overage: €0.018/task equivalent (your cost ~€0.006 at scale)
Pro overage: €0.012/task equivalent (your cost ~€0.004 at scale)
Operator sets a hard monthly overage ceiling: "never charge me more than €X extra"
Layer 4 — Context compression (hidden cost lever)
Org memory retrieval: top-10 chunks only, not full knowledge base
Company DNA: compressed to 800 tokens max (summary version for Tier 1 tasks)
Task history: last 5 comments only, not full thread
Goal ancestry: title + one-line summary per level, not full descriptions
This alone reduces average context by 40-60% vs naive injection
What to build in the platform vs what to monitor:
Build into the platform: token budgets per tier, context truncation, overage alerts, hard monthly cap.
Monitor manually at first: per-customer cost vs revenue weekly. Flag any customer where LLM cost exceeds 35% of their plan MRR. Those customers need to be upsold to Pro or their task mix needs adjustment.

Why the "abuse case" can't happen
20M token monthly ceiling → 2,000 T3 tasks = 60M tokens → hard blocked at 20M
10% T3 cap on Growth → 200 T3 tasks max per month at Growth tier
Worst case with caps: 200 T3 + 1,800 T1/T2 = €60 + €32 = €92 on €399 plan = 77% margin
The caps are your business model. They are not optional features.
The bottom line: With model routing + token caps + tier limits, your worst-case gross margin on any plan is ~63%. Your average gross margin at realistic usage is 80-85%. The business works. Without these three controls, it does not.
